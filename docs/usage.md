# 使用手册

[English](usage.en.md) | **中文**

本手册说明 napm 的日常操作。安装和第一次启动见 [README](../README.md)。

网页有中文和英文两种界面，用顶栏的语言按钮切换，选择保存在浏览器里。第一次访问时页面跟随浏览器语言。

## 准备访问令牌

napm 通过目标站点的管理接口读取用户并调整余额，所以每个平台需要一个个人访问令牌（PAT）。

前提：

- 目标站点运行 new-api v1.0.0-rc.41 或更新版本。
- 你能以管理员身份登录目标站点。

步骤：

1. 登录目标站点，进入「安全设置」。
2. 创建访问令牌，授予 `user:read`、`user:write` 和 `group:read` 三项权限。要采集用量（见[查看用量](#查看用量)），再加上 `log:read`。令牌以 `nap_` 开头。
3. 复制令牌。目标站点只在创建时显示它。

访问令牌只能在目标站点手动创建，不能用另一个访问令牌创建。令牌所属账号必须是目标站点的管理员。

## 添加平台

只有 root 管理员能添加、修改和删除平台。

1. 打开「平台管理」。
2. 填写名称、URL 和令牌，点击「添加」。URL 以 `http://` 或 `https://` 开头，不能包含用户名和密码。
3. 保存后，令牌不会再显示。修改平台时，令牌留空表示保持原值。

删除平台会同时删除该平台的统计、定时任务、执行记录和管理员授权。

## 管理管理员

只有 root 管理员能管理管理员账号。

1. 打开「管理员」。
2. 在末尾一行填写用户名和密码（至少 8 个字符），勾选该管理员可以管理的平台，点击「新增」。
3. 普通管理员登录后只看到被勾选的平台。
4. 勾选「root」会让该账号成为 root 管理员，可以管理全部平台和管理员。
5. 勾选「只读」会让该账号只能查看：能看被授权平台的统计、用户、用量、任务和执行记录，不能刷新、采集、调额、改任务，也不能增删平台和管理员。只读账号的 API 令牌同样只读，它仍可管理自己的令牌。root 不能同时是只读。

修改某位管理员的密码或权限后，该管理员已登录的会话立即失效，需要重新登录。root 管理员不能取消自己的 root 权限，也不能删除自己。

## 查看统计

「统计」页显示最近一次刷新的结果：用户数、总余额、总用量、请求数，以及每个分组的同样四项。金额以美元显示，按目标站点的 `quota_per_unit` 换算。

点击「刷新统计」会读取目标站点的全部用户并重新汇总。用户很多时刷新需要一段时间，因为 napm 对同一平台的请求至少间隔 600 ms，每页读取 100 个用户。刷新期间按钮显示「刷新中…」，完成后页面自动更新。

「用户」页逐页列出目标站点的用户，可以按关键词（用户名、邮箱或 ID）和分组筛选。该页的余额以原始额度显示。

## 查看用量

「用量」页回答「钱花在哪、什么时候、谁在用」。它的数据来自目标站点的数据看板（`/api/data/`），需要平台令牌带 `log:read` 权限，站点也要开着数据看板。

1. 打开「用量」，点击「采集用量」。第一次会回填最近 12 个月，之后每次只拉新增的部分。回填很长时会分块执行，中途失败后再点一次从断点继续。
2. 在「定时任务」里新增类型为「采集用量」的任务，例如 `0 * * * *`，让数据保持新鲜。
3. 页面上方选择最近 7、14 或 30 天。

页面显示四项指标（消耗、请求、Token、活跃用户，都带与前一个同长度周期的对比）、一组「看点」、每日消耗柱图、一天里的请求分布，以及按模型和按用户的排行。

「看点」每一条都是页面用你的数据算出来的，没有数据支撑的不会出现：

- 与前一周期相比涨跌；按最近 7 天日均推算一个月的消耗。
- 异常日：某天的消耗高过常态（中位数）三个离散度，且至少高 75%。柱图上用描边标出。
- 单个用户或模型占比过高；涨得最多、降得最多的用户；新出现和不再出现的用户数。
- 一天里最安静的连续 4 小时，适合安排停机或批量调额，以及最忙的一小时；周末明显低于或高于工作日。

这些分析都在你的浏览器里完成，服务器只保存小时级的原始行。「天」按你电脑的本地时区划分。今天还没过完，不计入。用量数据默认保留 12 个月，用 `--usage-months` 调整，超出的行在每次采集后删除。

## 调整余额

1. 打开「调整余额」。
2. 选择模式：
   - 增加：在当前余额上加上金额。
   - 扣减：从当前余额中减去金额。
   - 设为：把余额设置成金额，结果与之前的余额无关。
3. 输入金额，选择单位：「美元」按目标站点的 `quota_per_unit` 换算成额度，「原始额度」直接使用输入的数值。
4. 选择目标：「整个分组」并填写分组名，或「指定用户 ID」并填写以逗号分隔的用户 ID。同一个 ID 写多次，只处理一次。
5. 点击「执行」，确认对话框中的内容。

调整在后台执行，页面立即返回。在「执行记录」页查看进度和结果。

napm 对每位用户逐个调整。某位用户失败时，napm 记录原因并继续处理其他用户。下列情况会让某位用户失败，而不影响其他用户：

- 扣减的额度大于该用户在这次执行开始时的余额。new-api 本身允许余额变为负数，napm 不允许。
- 增加后的余额会超过 new-api 的余额上限（2^53 − 1）。
- 目标站点拒绝了请求，或指定的用户不存在。

如果输入的金额本身超过余额上限，整次执行失败，不会调整任何用户。

napm 不会自动重试失败的调整。

## 设置定时任务

1. 打开「定时任务」。
2. 填写任务名称，选择类型：「刷新统计」、「采集用量」或「调整余额」。
3. 填写执行时间表达式。支持两种写法：
   - 5 段 cron 表达式，顺序为分、时、日、月、周。例如 `0 3 * * *` 表示每天 03:00。
   - `@every <间隔>` 或 `@daily` 等预定义写法。例如 `@every 6h` 表示每 6 小时。
4. 类型为「调整余额」时，同时填写模式、金额、单位和目标，规则与立即调整相同。
5. 点击「新增任务」。

时间按运行 napm 的机器的本地时区计算。勾选或取消任务行的「启用」框可以启用或停用任务。

同一个平台一次只运行一个任务。定时任务触发时，如果该平台已有任务在运行，这次触发不会执行，并在执行记录中留下状态为 `skipped` 的一条。

### 定时「增加」不是幂等的

new-api 的调整接口没有去重机制，napm 也不保存已调整的流水。因此定时「增加」每次触发都会再加一次。需要让余额回到固定值时，使用「设为」。

## 查看执行记录

「执行记录」页列出该平台最近 50 次执行。每条记录包含开始时间、类型、内容、来源、状态和「成功/总数」。「来源」为触发的管理员用户名，或 `cron`（界面显示为「定时」）。执行记录里保存的错误信息由服务端在执行时写入，英文界面下仍是中文。

状态的含义见[参考](reference.md#执行状态)。一次执行有失败的用户时，记录下方显示最多 50 条错误，每条包含用户名、用户 ID 和原因。

## 用 MCP 连接 AI 客户端

napm 提供 MCP 接口，AI 客户端可以用你的身份读取统计、调整余额、管理定时任务。

1. 登录网页，打开「令牌」，点「生成令牌」。root 也可以在「管理员」页替任何管理员生成。
2. 点「显示」看到完整令牌和一段客户端配置，点「复制」复制令牌。
3. 把配置填进支持 HTTP 传输和自定义请求头的 MCP 客户端。地址是 `<napm 地址>/mcp`，请求头是 `Authorization: Bearer <令牌>`。

每个管理员只有一个令牌，随时可以看到。点「重新生成」会换一个新的，旧的立即失效，使用它的客户端要改成新令牌；点「删除」则不再有令牌。

令牌的权限与你相同。你只能管理被授权的平台，令牌也一样；root 的令牌可以调整所有平台的余额，请像对待密码一样保管。root 能在「管理员」页看到所有管理员的令牌，管理员只能看到自己的。令牌丢失、泄露或不再使用时，重新生成或删除它，使用旧令牌的客户端立刻失去访问。修改你的密码也会使令牌失效。令牌不能生成或删除令牌，也不能新增、修改、删除管理员账号，这些只能在网页里登录后做。

AI 客户端调用 `adjust_quota` 会真实修改余额，且「增加」和「扣减」重试会重复生效。给 AI 客户端授权调额之前，先在测试平台上试一遍。和网页一样，成功的写操作（刷新、调额、增删改任务）会记入操作记录，操作人是令牌的主人；读取不记录，被拒绝或校验失败的请求也不记录。工具清单见[参考](reference.md#mcp-接口)。

## 查看操作记录

「操作记录」页列出操作，新的在前，一次显示 200 条，点「加载更早的记录」继续往前看。root 看到所有管理员的操作，其他管理员只看到自己的。每条记录包含时间、操作人、平台、操作和详情。

记录的操作有：登录、刷新统计、调整余额、新增或修改或删除任务、添加或修改或删除平台、新增或修改或删除管理员、生成或删除令牌。详情只写这次改了什么，不写令牌和密码。登录失败不记录。

定时任务自己触发的执行不在这里，请看「执行记录」页，来源为 `cron`。创建或修改任务的人会出现在这里。

删除管理员或平台后，已有的记录仍然保留。被删管理员的记录只有 root 能看到，同名重新创建的账号看不到。记录不会自动清理，需要时可以直接删除数据库 `audit` 表里的旧行。

## 排查问题

### 添加平台后刷新统计失败

执行记录中的错误给出原因：

| 错误信息 | 原因与处理 |
| --- | --- |
| `HTTP 401` 或 `HTTP 403` | 令牌无效、已被删除，或缺少权限。在目标站点重新创建令牌，并授予三项权限。在 napm 的「平台管理」中更新令牌。 |
| `unexpected response (is the URL a new-api site?)` | URL 指向的不是 new-api 站点，或指向了站点的前端而非 API。检查 URL，只填写站点根地址。 |
| `HTTP 429` | 触发了目标站点的限流。napm 读取时会按 `Retry-After` 等待并最多重试 3 次。如果仍然失败，用 `--interval` 增大请求间隔后重启。 |
| 连接超时或拒绝连接 | napm 所在的机器无法访问该 URL。在运行 napm 的机器上用 `curl <URL>/api/status` 验证。 |

### 一直无法登录

连续登录失败 5 次后，该客户端 IP 和该用户名各被锁定 1 分钟，期间返回 HTTP 429。等待 1 分钟后再试。

### 重启后需要重新登录

会话保存在内存中。重启 napm 会使所有人退出登录。

### 调额执行状态是 `interrupted`

napm 在这次执行中途被停止，例如进程被终止或容器被重启。记录中的「成功/总数」是下限：被停止时，最后一位用户可能已经调整成功，但尚未计入。记录也不保存具体处理了哪些用户。

处理方法：

1. 到目标站点核对相关用户的余额。
2. 模式为「设为」时，直接重新执行，结果相同。
3. 模式为「增加」或「扣减」时，不要整批重新执行，否则已处理的用户会被再调整一次。只对未处理的用户重新执行。
